Verified findings

What breaks and why

Each item starts with the visible consequence, then traces the cause and the smallest safe correction.

01 A file whose timestamps start above zero can begin on the wrong frame and run too long. Timestamp normalization · single export Blocker

Failure scenario

A 24 fps H.264 source began at timestamp 1.000 and placed keyframes every two seconds. A requested 3.000–7.000 second cut was treated as already sitting on a keyframe. The exported file began on the wrong image and contained 122 video frames instead of 96: about 5.08 seconds instead of 4.00.

Cause

The keyframe scan returns the source’s original timestamps, but the requested clip range is measured from the beginning of the visible content. The implementation compares those two different timelines directly. In this case, source timestamp 3.000 was mistaken for content time 3.000, so the direct-copy shortcut ran when it should not have.

Smallest safe fix

Read the video stream’s start timestamp, convert every probed keyframe to the same zero-based timeline used by clip ranges, and use that normalized value for the comparison and cut. Add a media test with a +1 second start timestamp that checks the first frame and exact frame count.

02 Merging H.264 and HEVC clips can produce a file whose later section does not decode. Stream compatibility · merge export Blocker

Failure scenario

A one-second H.264 clip followed by a one-second HEVC clip joined without an error. The result identified its only video stream as H.264. When playback reached the HEVC section, the decoder reported invalid H.264 data and returned no usable frames for that section.

Cause

The merge path cuts every selection independently, then joins all temporary files without checking that they describe the same kind of video. The first file’s description becomes the description for the entire result, even when later packets use another codec.

Smallest safe fix

Inspect all unique sources before creating temporary or final files. Refuse the merge with a clear message unless their video descriptions are compatible. At minimum compare codec, pixel layout, dimensions, frame rate, and the stream parameters required by the final container.

03 If the first merged clip is silent, sound from every later clip disappears. Audio layout · merge export Blocker

Failure scenario

A silent one-second H.264 clip was merged before a one-second H.264 clip with AAC audio. The operation completed without an error, but the result contained only a video stream. Reversing the order retained audio, so the visible result depends on selection order.

Cause

The first temporary file defines which streams the joined file contains. The app already checks which sources have audio, but the Smart Cut merge does not use that information to make every temporary segment share the same audio layout.

Smallest safe fix

Build the merged video and audio timelines separately, inserting correctly timed silence for clips without audio, then combine them. If that work is deferred, refuse mixed silent/sound merges instead of silently deleting sound.

04 Cancel can be ignored when the click lands between two processing stages. Cancellation · sequential work Should-fix

Failure scenario

The user clicks Cancel after the opening frames finish but before the body copy begins. No process exists during that short gap, so the cancel action stops nothing. The next process starts and the export continues even though the UI accepted the click.

Cause

Cancellation only terminates the process that is active at that exact moment. It does not record that the whole export was cancelled, and the next stage does not check for a pending cancel request.

Smallest safe fix

Store a cancellation generation or flag for the entire export. Check it before every new process starts and after every process returns. Reset it only when a new top-level export begins.

05 A failed or cancelled export can leave a broken file with the final filename. Output safety · error handling Should-fix

Failure scenario

When the direct-copy shortcut, final audio/video write, or final merge is interrupted, the export folder can retain an incomplete `.mkv`. A forced cancellation reproduced this as a zero-byte file that looked like the requested result.

Cause

Those final stages write straight to the user-facing filename. Temporary working folders are cleaned, but no guard removes a final file that was opened before the process failed.

Smallest safe fix

Write every final stage to a sibling temporary filename, then rename it only after success. Delete that temporary file on error or cancellation.

06 The safety fallback can accept a body that is visibly too short or too long. Wrong-footage guard · frame count Should-fix

Failure scenario

For a 20-second body at 24 fps, 480 frames are expected. The current threshold accepts 432 or 528 frames—two seconds of missing or extra footage—as close enough. If frame counting itself fails, the code assumes the count was perfect and skips the fallback.

Cause

The allowed difference grows to ten percent of the clip, even though the review contract says an unnecessary fallback is safer than accepting the wrong footage. A failed inspection is also converted into an artificial success.

Smallest safe fix

Use a small fixed allowance measured in frames and treat an unavailable count as a reason to re-encode. For stronger protection, also confirm that the body begins on the intended source picture instead of relying on length alone.

07 The verification script can approve wrong content and reject a valid stream copy. Approval tool · false pass and false failure Should-fix

Failure scenario

Audio or video packets with the same byte length are treated as the same content. Constant-size audio can therefore appear aligned even when it came from the wrong moment. In the opposite direction, a generated H.264 sample used the intended stream-copy pipeline but the script failed it because 19 of 21 inspected packet sizes matched and its threshold demanded 20.

Cause

The script compares packet lengths, not packet contents, and its matching rule assumes only one packet may change during container conversion. It also omits the app’s post-copy fallback, so it does not always test the path the app will use.

Smallest safe fix

Hash normalized packet contents for video, compare decoded audio fingerprints at the requested time, and mirror the fallback before running checks. Keep the allowed container-only differences explicit rather than inferring identity from byte length.

Merge gate

Re-run the review after these three observable outcomes are impossible:

  1. A non-zero-timestamp source exports the same first frame and frame count as its requested zero-based range.
  2. A merge either rejects incompatible video before writing or produces a fully decodable result.
  3. Mixed silent/sound clips retain a correct audio timeline regardless of selection order.
