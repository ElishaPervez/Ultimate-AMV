Dead Frame
Remover

Anime doesn't draw 24 pictures a second. It draws about 10 and holds each one for two or three frames. This tool throws the held copies away, so a clip contains only real drawings.

01

What's wrong right now

Open any anime clip in your library and step through it one frame at a time. For long stretches the picture doesn't change at all — you press next, next, next, and you're still looking at the same drawing. That's not a bug in the file. It's how the show was made: the animators drew one picture and held it on screen for two or three frames to save work. A 24-frame second usually contains about 10 actual pictures.

Every tool you point at that clip is fooled by it. Frame Interpolation is the loudest example. It works by inventing a picture halfway between two frames. When both frames are the same held drawing, there is no halfway — so it invents a copy. You get a 60fps file that still moves in the same lumpy 10-steps-a-second rhythm, just with more frames wasted on saying nothing. You paid GPU time and file size for zero smoothness.

The consequence you can see

Smooth a 24fps anime clip to 60fps today and it still judders. Not because the smoothing is broken — because two thirds of what you fed it was the same picture repeated, and the smoothing dutifully repeated it back at you.

The same held copies bloat every clip you cut. A third to a half of every file on your disk is frames that say nothing new.

02

How to see it for yourself, in ten seconds

  • Take any anime clip out of Scene Splitter — a dialogue shot works best, something where a character is talking but not moving much.
  • Run it through Frame Interpolation at 2×.
  • Play the result. It has twice the frames and looks exactly as choppy as it did before.
  • Now step through the original frame by frame in the comparison player. Count how many presses it takes before the picture actually changes. On most shots it's two. On slow dialogue it's three.

Those repeated presses are what this tool deletes.

03

What the tool does

Same shape as Frame Interpolation: drop clips on the panel, they stack up in a queue, you set it once, it works through the lot. Two things are different — a measuring step in the middle so the dial can tell you the truth instantly, and a preview you have to watch before the tool will let you export anything.

A Drop clips Drag files or a folder in, or pick several. They queue up exactly like they do for smoothing.
B It measures Each clip is read once at thumbnail size and scored: how different is every frame from the one before it. A 30-second clip takes about two seconds.
C You set the dial Drag sensitivity and the count updates the instant you move — no re-reading the file, it's re-reading the scores it already has.
D You preview Builds a quick low-resolution version of the selected clip at that setting and drops it into the right-hand player. A few seconds. Move the dial and preview again — the new one replaces the old.
E You export The button at the bottom, locked until you've previewed. Runs the whole queue at the setting you watched. Each file lands beside its own original with a suffix.
The export button locks itself again

Touch the dial after previewing and Export goes back to greyed out. It has to — otherwise you'd ship a setting you never actually watched, which is the exact thing the preview exists to prevent. Clicking a different clip in the queue locks it too, so the two players are never showing you two different clips. Preview again and it lights back up. Changing format or quality does not lock it — the preview is low-resolution and was only ever vouching for the dial.

What the preview is and isn't

It's rendered small and fast, so it's for judging timing and motion — did the pan survive, did the dialogue collapse cleanly. It is not for judging picture quality. The exported file uses your real output settings at full resolution.

Yes, it re-encodes — and you control how

Frames can't be removed without rebuilding the file, so every export is a re-encode. You get the same controls as everywhere else: pick H.264 MP4, HEVC MP4, H.264 MKV or ProRes MOV, then Quality, VBR or CBR with a slider for the number. Each format is one button — the app uses your graphics card's encoder when there is one and the processor when there isn't, so there's no CPU-versus-GPU choice to make. The only tell is the little label on the number field: CQ means the card is doing it, CRF means the processor is. ProRes is the exception with no quality dial at all — its profile fixes that, so the whole row disappears when you pick it.

04

The dial, and where it bites

Two frames are never byte-for-byte identical after video compression — there's always a little noise. And a slow camera pan changes every frame by a tiny amount. So the tool has to draw a line: below this much change, call it a copy. That line is the dial, and it is the entire interface.

The failure the dial can cause

Push sensitivity too far and the slow pan gets eaten. Those frames each moved by a few pixels — real motion, not a held drawing — but they moved less than your line allows, so they get binned. The pan comes out as a hard jump instead of a glide. The count on the readout is your defence: if a clip you know is mostly panning reports 60% removed, the setting is wrong for that clip.

Sketch, not final visuals — it inherits the same shell, queue and output controls as Frame Interpolation.

The queue shows each clip's before-and-after frame count as soon as it's been measured, so you can spot the outlier before you export anything. Click any row and the dial reads against that clip. The setting still applies to the whole queue — you're tuning on one and trusting it across the rest, which is why the per-clip counts in the list matter.

The two players sit side by side and run independently, because the cleaned clip is genuinely shorter. There's no wipe slider and no synced scrub — those only make sense when both files share a timeline, and these don't.

The bottom bar is the whole safety mechanism. Preview sits next to Export, and the line of text beside them is always telling you which state you're in: no preview yet, preview matches the dial, or dial moved — preview again. Export is only clickable in the middle state. That's why there's no output folder to choose either — the destination is decided (next to each original, with your suffix), so the only two things you can get wrong are the dial and the format, and you've watched the dial.

07

Two ways to build it

Recommended

Reuse the smoothing tool's export machinery

  • Your output settings behave identically to the ones you already know, because it's the same code — not a lookalike.
  • The live count is a promise, not an estimate: the same measurement that feeds the dial is the one that decides what gets dropped.
  • Nothing new to install. It runs on the pieces the app already ships, and works the same on a machine with no graphics card.
  • The shared export code has to be lifted into a place both tools can reach, so Frame Interpolation needs retesting after.
Alternative

Build it standalone, sharing nothing

  • Frame Interpolation is not touched at all, so it can't break.
  • You end up with two separate sets of output settings that drift apart over time — a fix to one silently misses the other.
  • The count on the dial becomes an estimate. It can disagree with what actually comes out, which undermines the one control the whole tool rests on.

Either way the work splits into five pieces that can be checked separately: the measuring step, the dial-to-frame-list decision, the fast preview render, the full export, and the panel. The second one is worth testing hardest — feed it a clip that's known to be on 2s and it must remove exactly half, no more. Preview and export are the same code with different quality settings, which is what makes the preview trustworthy: what you watched is what you get, just bigger.

08

What could still go wrong

  • Grain and film noise defeat it. An older show with heavy grain changes every frame slightly, so nothing looks like a copy at a careful setting and nothing gets removed. You'd have to push the dial well right on those, and the live count will tell you when you're in that situation.
  • You preview one clip and export forty. This is the sharpest edge in the design. A dialogue shot and a chase shot want different settings, and the one you watched might be the only one that survives it. The per-clip counts in the queue are your warning system — a clip reporting 60% removed when its neighbours report 30% is the one to check — but the tool will not stop you.
  • A second export overwrites the first. Files land beside the original with a fixed suffix, so exporting the same clip twice at different settings writes over the earlier one. Change the suffix between runs if you want to keep both.
  • Re-encoding costs quality. Frames can't be removed without re-encoding, so every cleaned clip is a second-generation copy. Use the quality-based setting rather than a bitrate cap and it's negligible, but it isn't free.
  • Very long clips measure slowly. Reading is at thumbnail size so it's quick, but a ten-minute file is still a ten-minute read. Measuring happens per clip as it enters the queue rather than all at once, so the first clip is ready to tune while the rest catch up.
